# 対話中の本人による訂正

2026-11-18調査。添付の既存画面では、AI相談後に行動と日付を本人が手入力し、確認して保存する導線が見える。従来の共有指示には既出の日付を保持する規則はあるが、後の明確な訂正を優先する規則はなかった。古い内容が確認案に残る可能性は仮説であり、実AIの誤りを観測したものではない。

## 調査と選択

- [Retrium公式ヘルプ](https://support.retrium.com/articles/how-do-action-items-work-in-retrium/)は、行動の記入、担当者と目標完了日の追加、完了操作を説明している。
- [Parabol公式ヘルプ](https://www.parabol.co/support/how-to-use-the-tasks-view-in-parabol/)は、担当者別のタスク一覧とチーム内の担当・状態表示を説明している。
- [Scrum.orgの実務家記事](https://www.scrum.org/resources/blog/ditch-unfinished-action-items)は、ふりかえりで決めた行動のフォロー不足を問題として論じ、明確な担当や進捗確認を提案している。

これらは製品の説明と記事著者の見解であり、RetroLoop利用者の実測でも、訂正指示の効果を示す実験でもない。候補Aは本人が後から訂正した行動・日付を確認案に反映する共有指示で、優先シナリオの確認・修正に直結し、小さく実装できる。候補Bは保存後の担当別タスク・状態一覧で、フォローには役立つ可能性があるが、保存後の機能拡張が大きい。今回はAを選ぶ。競合との機能一致は目的ではない。

## 変更と検証

本人の明確な訂正はその項目の最新回答を使い、曖昧な訂正は推測せず質問する指示を追加。既存のテスト本文を変更せず、台本モックで訂正、未保存、本人の確認・保存、元Problemを含む再表示を確認するシナリオと、実Routeからモデル境界への指示伝達のテストを追加した。台本モックはモデルの意味理解を証明しない。画面PNGは新テストの実行時に生成される予定で、旧版の比較画像ではない。

ホストでテストや実AIは実行していない。独立ClaudeレビューとCIは未実施で、指摘・対応もまだない。レビュー後の正確なSHAを対象に、既存Plus認証と架空データを使った最大3往復の一時UI検証が必要。実AIの接続、応答品質、ブラウザー内保存と、モックCIによる本番相当の認証・DB保存は別々に記録する。モデル差、全文応答、遅延と未完了範囲を残す。本番Geminiでの品質はこの限定検証だけでは証明できない。

週次では訂正が確認案に反映されたか、未指定事項が捏造されていないか、曖昧な訂正への質問が負担にならないかを判断する。
