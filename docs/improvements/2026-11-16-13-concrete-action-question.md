# 曖昧な改善宣言から本人の具体的行動を引き出す

対象: 2026-11-16-13 JST、承認済み計画の実装。一つの改善として共有AI指示とその回帰・限定検証入力を変更する。

## 観測と仮説

添付の ai-chat / board-color / board-group / board-vote 画面で、本人が行動・日付を入力して保存内容を確認する導線を確認した。開発Issue表示だけでは障害と断定しない。ベースラインの実行失敗ログは提示されていない。

変更前の `src/lib/llm/chat-guidance.ts` は不足情報への質問と、行動・担当・日付を本人が述べた場合の確認案を指示しているが、抽象的な宣言を具体化済みと扱わない条件がない。これは静的な指示の不足の観測であり、実モデルが今回誤応答したという証拠ではない。「気をつける」が確認案へ進む可能性と、追加質問が具体化を助けることは検証対象の仮説である。利用者インタビューや改善率は取得していない。

  SMARTな行動を推奨し、担当・目標日・完了操作を案内する。行動を実行可能にする材料だが、AIの問い返しの効果やRetroLoop利用者の問題を実証するものではない。

## 実装と変更後の期待

「気をつける」「意識する」「改善する」だけなら具体化済みとせず、本人が何を対象にどんな動作をするか一つ質問する。AIによる行動案の補完を禁じる。既述の担当・具体日付を保持し、具体的な対象・動作が答えられたら不要な再質問をせず確認案へ進む。保存可否を判定する新しい制限は追加しない。

SDK変更は行わない。同梱のNext Server Actionsガイド、aiのstreamText / convertToModelMessages / useChatリファレンス、Promptと変換関数のソース、@ai-sdk/reactのuseChat型を静的に確認した。Promptのsystemは非推奨だが既存互換の型があり、今回API移行は混在させない。

## 回帰防止と検証の境界

追加ファイル `e2e/concrete-action-guidance-route.spec.ts` は隔離バンドルで実Routeの共有指示をモデル境界で捕捉する。認証本人を使うツール引数、チーム所属チェック、既存ステップ上限も確認する。モデル・認証・DB・費用設定はスタブで、外部呼び出しはしない。

追加ファイル `e2e/concrete-action-question.spec.ts` はダミーDBと台本モックで以下を検証する。

1. 自分のProblemを選び「担当は私、日付は2026-11-23、行動は気をつける」を送る。
2. 一問の応答後に本人が「自分のPRの依頼時刻と完了時刻を一件記録」と答える。担当・日付を保持した未保存の確認案を表示する。
3. 各応答後に行動・日付が自動入力されず、Tryがまだゼロであることを確認する。
4. 本人が手入力して確認し、行動と日付を修正して再確認する。確認段階でも未保存であることを確認する。
5. 明示保存で本人作成の一件だけが保存され、修正内容がDBと再読み込み後のTryに一致する。

新規PNGは相談前 `e2e/__screens__/concrete-action-question-before.png` と保存・再表示後 `e2e/__screens__/concrete-action-question-after.png`。両方とも候補版を実行した際の画面で、旧SHAの画面とは扱わない。既存E2E本文・アサーションは編集していない。

台本モックはモデルの判断を証明しない。既存 `live-scenario.mjs` の第二入力を、前回Try実施済みの回答に続く曖昧な行動・本人担当・具体日付に変更した。第一入力の過去Try確認と第三入力の具体回答は維持し、最大3往復を維持する。verifierには第二応答が質問を含むことと既存の捏造語例を含まないことの限定チェックを追加し、既存の応答検証・隔離・タイムアウト・合成保存を維持する。

独立Claudeレビュー後の確定SHAをコントローラーが既存Plus経路で限定検証する。第二応答が対象・動作を一つ質問し、担当・日付を聞き直さず、本人未指定の行動を提案していないかは全文を評価する。第三応答で本人回答が保持され未保存と示されることも評価する。限定語句チェックだけを意味の合格判定にしない。接続・対話品質・ブラウザー内合成保存を、本番相当の認証・DB保存を通すモックCIと区別する。本番GeminiとPlus側モデルの差、各応答・遅延・未完了範囲を検証記録に残す。
